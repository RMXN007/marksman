# 📂 Project Structure & Architecture Flow

This document breaks down the entire directory structure of the project, explains what each folder contains, and outlines the architectural flow of the application from data ingestion to the final user interface. Use this to understand how all the pieces connect and to help explain the project architecture.

## 1. Directory Structure & Data Locations

Your project directory (`c:\Users\acer\Desktop\anu project\`) is organized into several key components:

### 📁 `Marksman Training Data/`
This is your **Raw Data Repository**.
- **Images:** Contains the 518 original `.jpg` target images.
- **Labels:** Contains the 518 original YOLO `.txt` files generated by the initial heuristic script (or modified via LabelImg).
- **`classes.txt`**: A simple text file required by `labelImg` defining the `bullet_hole` class.

### 📁 `bullet_hole_dataset/`
This is your **Structured Training Dataset**, prepared specifically for YOLO to ingest.
- **`data.yaml`**: The master configuration file telling YOLO where the training and validation images are, and what the classes are.
- **`images/train/` & `images/val/`**: The 518 raw images automatically split into 80% training data (414 images) and 20% validation data (104 images).
- **`labels/train/` & `labels/val/`**: The corresponding `.txt` bounding box coordinates split to match the images.

### 📁 `runs/bullet_hole_detection-2/`
This is your **Model Output & Metrics Hub**. Every time Ultralytics YOLO trains, it saves the results here.
- **`weights/best.pt`**: The holy grail of the project! This is your final, trained neural network model that is used by the application for inference.
- **`results.png` & `confusion_matrix.png`**: Visual graphs showing the training loss, precision, and recall over the 10 epochs.

### 📁 System Scratch Directory (Scripts)
The Python scripts powering the logic were built in the system's scratch folder to keep your Desktop clean, but they are the core engine of the project:
- **`prepare_dataset.py`**: The script that shuffled and moved your raw data into the structured `bullet_hole_dataset/` folder.
- **`train.py`**: The script that loaded `yolov8n.pt` and trained it on your data using the CPU.
- **`inference.py`**: A command-line script to test the model on a single image.
- **`app.py`**: The Streamlit Graphical User Interface (GUI) code.

### 📁 Documentation
- **`Project_Overview.md`**: High-level summary of the training process and project goals.

## 2. Application Flow (How it all works)

When explaining this project, you can break the architecture down into **4 distinct phases**:

### Phase 1: Data Preparation Pipeline
1. Raw images are collected from the shooting range.
2. Bounding boxes (X, Y, Width, Height) are generated for every bullet hole (either automatically via OpenCV edge detection or manually via tools like `labelImg`/`label-studio`).
3. The raw data is algorithmically split into a structured `Train` and `Validation` subset so the model can learn on the training data and test itself on the validation data.

### Phase 2: Model Training Engine
1. The project uses **YOLOv8 Nano**, a state-of-the-art Convolutional Neural Network designed for real-time object detection.
2. The model reads the `data.yaml` file to locate the training images.
3. During training (10 epochs), the model looks at an image, guesses where the bullet holes are, compares its guess to the actual `.txt` label, calculates its "Loss" (error margin), and updates its internal weights to improve on the next pass.
4. The final optimized mathematical weights are saved to `best.pt`.

### Phase 3: The Inference Backend
When a new, never-before-seen image is passed to the system:
1. The `ultralytics` library loads the `best.pt` file into memory.
2. The image is scaled down to 320x320 pixels (the size the model was trained on).
3. The neural network processes the pixels and outputs a list of coordinates and confidence percentages for anything it thinks is a bullet hole.

### Phase 4: The Graphical Frontend (Streamlit)
1. The user opens the web app in their browser and uploads an image.
2. `app.py` takes the image, saves it temporarily, and passes it to the **Inference Backend**.
3. Once the model returns the bounding box coordinates, `app.py` uses the `cv2` (OpenCV) library to visually draw red rectangles directly onto the uploaded image.
4. The application renders the newly drawn image, the total count of bullet holes, and a detailed data table back to the user on the webpage.
